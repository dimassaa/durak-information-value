The endgame rule, and why it distorts every rate here

The win check runs the moment a card leaves the hand, so an attacker playing a last card wins outright and the defender never gets to answer. On this dataset most games end that way. This is spec 3.4's documented rule set rather than a defect, but it compresses the endgame: a 'close' game here is closer than a reader of the number would assume.

A positional effect can be told from a dealing effect here

The two seat counts are near-equal, so a rate difference between two strategies is about the strategies and not about which seat they were dealt into. Read the field names carefully though: 'first_attacker_p0_wins' and 'first_attacker_p1_wins' count SEAT wins, not wins by the first attacker. Under RULE_DERIVED the first attacker is decided by the rules and is not seat 0, so the dataset's actual first-attacker win rate is a different number from either field. TRACKED IN IMPROVEMENTS.md.

What this comparison does and does not establish

These two readings were measured in SEPARATE tournaments, so they are not a paired comparison and the gap is not a significance test. Each rate carries its own interval; where the intervals overlap, the rule reading does not explain the difference. The throw-in rule is a genuine ambiguity in the source document rather than a tuning knob, so both readings are reported rather than one being chosen.

The 36 vs 52 deck check was not run

The 36 vs 52 deck sensitivity check was NOT run: this dataset played only the 36-card deck, so deck 52 is UNMEASURED. No rate is reported for it -- a zero would read as 'measured, and it is zero', which is a different and false claim.
